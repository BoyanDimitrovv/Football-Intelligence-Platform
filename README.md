# Football Intelligence Platform

Интелигентна уеб платформа за футболен скаутинг, която комбинира база данни,
машинно обучение (писано от нулата) и AI асистент, за да препоръчва футболисти
според нуждите на даден отбор.

Платформата работи **напълно офлайн** - няма външни CDN зависимости, няма
NumPy/Scikit-learn, няма изпращане на данни към външни услуги.

## Функционалности

- **Търсене и филтриране** на футболисти по име, позиция, отбор, националност,
  възраст, оценка и пазарна стойност, с девет режима на сортиране.
- **Сравнение** на до четири играчи - таблица, радарна диаграма на
  атрибутите и линейна диаграма на сезонната еволюция.
- **ML препоръки** - прозрачен score от пет компонента, всеки със собствено
  обяснение (виж „Как работи скорингът" по-долу).
- **Статистически графики** - собствен SVG библиотека (`static/js/charts.js`):
  donut, bar, grouped bar, line и radar диаграми, без Chart.js.
- **AI асистент** - чат, който разбира въпроси на български и отговаря с
  реални данни от базата (offline intent parsing, без външно API).
- **Детайлен профил** на играч - атрибути, сезонна история, разгъване на
  потенциала и сходни играчи.

## Изисквания

- Python 3.10+
- pip

Единствената външна зависимост е Flask (вж. `requirements.txt`).

## Инсталация

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

## Стартиране

```bash
python app.py
```

Приложението е достъпно на адрес `http://127.0.0.1:5000`.

При първо стартиране базата се пълни автоматично с демо данни и се обучава
моделът, така че няма допълнителни стъпки. Ръчно може да го направите с:

```bash
python -m database.seed    # пълни SQLite базата с демо данни
python -m ml.train         # обучи и запиши моделите в ml/model.json
```

## Демо данни

Базата съдържа **синтетичен демо набор** - 8 български отбора, 36 футболиста
с измислени имена и 4 сезона (2021/22 - 2024/25) статистики. Всичко е
детерминистично (фиксирано seed), за да се възпроизвеждат едни и същи числа.
Данните **не са реални** и не следва да се използват за реални трансфери.

## Как работи скорингът

Финалният скор на играча е прозрачна линейна комбинация от пет компонента:

| Компонент | Тежест | Какво измерва |
|---|---|---|
| `performance` | 0.34 | вероятност за силна кампания според ML модела |
| `position_fit` | 0.30 | съвпадение на атрибутите с изискванията на ролята |
| `availability` | 0.14 | форма, риск от нараняване, дисциплина, издръжливост |
| `value` | 0.10 | цена спрямо качеството (стойност за парите) |
| `age_fit` | 0.12 | възрастен профил спрямо етапа в кариерата |

Изискванията на клуба (минимална оценка, максимална възраст, максимална
цена) не скриват играча, а **намаляват** скора му, за да се вижда защо не
попада в списъка.

### Моделът

Логистичната регресия е написана от нулата (`ml/model.py`) - прозрачна и
лесна за обяснение при демонстрация. Обучението е **по един модел за всяка
позиционна група** (GK / DEF / MID / ATT), защото:

- етикетът („ще има силен сезон") е позиционно-зависим - нападателят носи
  головете и асистите, а защитникът никога;
- отделните модели учат **в рамките на позиционната група** какво прави един
  играч добър в сравнение със своите връстници.

Етикетите се поставят по топ 40% от индекса на изпълнение **в нормализиран
спрямо родната позиция вид** (защитникът се мери спрямо защитниците, а не
спрямо нападателите). Резултатът е интерпретируема класация - например
моделът за защитници научава, че чистите листове, дуелите и издръжливостта
водят до силен сезон, а не головете.

## Структура на проекта

```
Football-Intelligence-Platform/
├── app.py                     # Flask приложение, маршрути и JSON API
├── assistant/
│   └── bot.py                 # Асистент: intent разбиране и отговори
├── data/
│   └── raw/                   # JSON експорт на демо набора (генериран)
├── database/
│   ├── schema.sql             # DDL на SQLite базата
│   ├── db.py                  # Връзка и инициализация
│   ├── seed.py                # Демо набор и JSON експорт
│   └── repository.py          # Запитания към базата
├── ml/
│   ├── features.py            # Feature engineering и позиционни индекси
│   ├── model.py               # Логистична регресия + ModelBundle
│   ├── train.py               # Обучение и запис на моделите
│   └── recommender.py         # Скоринг, класация и обяснения
├── static/
│   ├── css/style.css          # Дизайн система
│   └── js/
│       ├── charts.js          # Собствена SVG библиотека с графики
│       └── main.js            # Филтри, сравнение, чат клиент
├── templates/                 # HTML шаблони (Jinja2)
└── tests/                     # Тестове
```

## Сигурност

Не се записват тайни ключове или пароли в кода. Конфигурациите, свързани със
сигурността, се четат от променливите на средата:

| Променлива | Назначение |
|---|---|
| `SECRET_KEY` | Ключ за Flask сесиите |
| `OPENAI_API_KEY` | Незадължителен - външно LLM за асистента |
| `ANTHROPIC_API_KEY` | Незадължителен - външно LLM за асистента |

Без зададени API ключове асистентът работи изцяло офлайн върху базата.

```bash
# Windows PowerShell
$env:SECRET_KEY = "..."
# Linux/macOS
export SECRET_KEY="..."
```
